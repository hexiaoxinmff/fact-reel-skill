# FactReel — 中文知识短视频

把选题做成一条**经得起查**的竖屏知识短视频。默认：1080×1920、30fps、30–45 秒、普通话旁白、烧录字幕、片尾来源卡。

## 硬规则（不可跳过）

1. **先查证，后写稿。** 事实表（`templates/fact-table.md`）未完成前，不写一句旁白。
2. **每个数字、日期、专名都要有来源。** 两处以上独立来源冲突时，用更一手的一方，并在事实表注明分歧。
3. **不许混口径。** 同一组对比数据只用一个统计口径；例外必须在画面脚注标明。
4. **估算要认账。** 插值、估算时长、示意复刻的画面/对白，必须在画面或片尾标注，不得冒充实测或原话。
5. **三道门必须停：** 事实表确认 → 静帧评审 → 成片校验。用户没点头，不进下一道门之后的阶段。
6. **不用付费 API key 也能跑完。** 配音默认用环境可用的 TTS；换音色/引擎是可选项，不是前置条件。

## 阶段流程

### 阶段 1 — 查证（读 `references/fact-check.md`）
- 拆选题为可核查的事实清单：事件、日期、数字、人物、结论。
- 联网核查，优先一手/强来源（官方、判决书、论文、权威媒体）。
- 输出事实表：事实 | 数值/表述 | 来源 | 核查日期 | 可信度。
- **门 1：把事实表交用户确认。** 未核实的条目要么删，要么降级标注，不许带病进稿。

### 阶段 2 — 写稿（读 `references/script-beats.md`）
- 结构：0–3s 钩子 → 每 3–4s 一个信息点（一个 Beat 一句旁白）→ 结尾一个可评论的问题。
- 总句数按目标时长反推：约每句 3.5–5 秒，40 秒 ≈ 9–11 句。
- 每句旁白只承载事实表里已有的事实；口语化，数字读法写成念稿形式（如「二零二五年一月」）。
- 输出分镜表（`templates/storyboard.md`）：Beat | 画面 | 旁白 | 预计时长（待实测回填）。

### 阶段 3 — 配音与计时（读 `references/captions-and-voice.md`）
- 逐句生成配音文件，逐句用 ffprobe 实测时长，回填分镜表。
- 场景时长 = 实测配音时长，不许用估算值排时间轴。
- 某句超时（>5.5s）先改稿重录，不要靠加速硬塞。

### 阶段 4 — 画面（读 `references/visual-grammar.md`）
- v0.1 只用「时间线卡片」模板：一 Beat 一卡，大数字/关键词优先，装饰不抢信息。
- 先渲 3 张关键静帧（钩子帧 / 中段信息帧 / 结尾帧）交用户看。
- **门 2：静帧通过后才写完整 composition。**

### 阶段 5 — 渲染与校验（读 `references/quality-gates.md`）
- 字幕用句级实测时间烧录；句内高亮如为估算，在项目说明中声明（见 captions 参考）。
- 渲染后 ffprobe 校验：分辨率、帧率、时长、h264 + aac、文件大小合理。
- **门 3：校验数据连同成片一起交付，不报“渲染成功”代替校验结果。**

### 阶段 6 — 发布包（读 `references/publish-pack.md`，用 `templates/publish-pack.md`）
- 封面帧从成片关键帧选，封面文案 ≤ 两行。
- 三平台各一份：抖音 / 视频号 / 小红书，标题、正文、置顶评论分开写，不一稿多投。
- 提醒用户按平台规则勾选 AI 生成内容标识；片尾来源卡不可删。

## 交付清单

- [ ] 事实表（含来源与核查日期）
- [ ] 分镜表（时长为实测回填）
- [ ] 成片 mp4（附 ffprobe 校验结果）
- [ ] 封面帧 png
- [ ] 发布包（三平台）
- [ ] 未核实/估算项的标注说明（如有）

## 不做什么

- 不做无出处的“盘点”“冷知识”拼稿。
- 不把合成/示意画面说成真实影像。
- 不自动发布到任何平台（发布由用户本人操作）。
- v0.1 不做：BGM 混音、多视觉模板、横屏长视频 — 见仓库路线图。
